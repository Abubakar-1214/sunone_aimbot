# 2026-11-25

## Aim lock fix: mouse overshoot / no stop on detected enemy

**Problem reported:** mouse jumps toward the detected point but does not stop/lock
there — it slides past it. User asked for "jahan detect hui wahan hi lock ho jaye".
Later: after a first fix the mouse stopped moving entirely.

**Attempt 1 (REJECTED — do not retry):** absolute cursor control
(`MOUSEEVENTF_ABSOLUTE` / `SetCursorPos`) with capture-region bounds.
It converged perfectly on the *OS cursor* in tests, but in-game the mouse
appeared frozen. Reason: FPS games read input through Raw Input (`WM_INPUT`) /
DirectInput and ignore the OS cursor position, so absolute moves are invisible
to them. Only relative deltas turn the view. `move_mouse_abs()` and
`get_cursor_pos()` remain in `logic/platform.py` but are NOT used by `mouse.py`.

**Final design — relative, closed-loop, self-calibrating (`logic/mouse.py`):**
- `_init_lock_controller()` holds all tunables; `_reset_loop()` clears
  per-target state (`_samples`, `_pending`, `_px_count_x/y`, `_invert_x/y`,
  `_cur_ratio`, `_last_ratio`, `_pending_expected`, `_human_hits`).
- `_update_calibration()` learns the REAL px-per-count from the previous step:
  `delta_offset / counts_sent`, folded in with alpha=0.5, plus
  `_learn_bias()` for constant per-step bias (rounding / internal scaling).
- `_learn_axis()` detects axis inversion by magnitude (flip if
  `|observed| > 0.9*|current|`, shrink if `< 0.65*|current|`) — avoids the
  ±140-count oscillation a naive sign test produced.
- `calc_movement()` returns relative counts, `(0,0)` = hard lock:
  1. outside `lock_max_zone_px` -> send nothing
  2. `dist <= deadzone_px` -> hard lock + dwell frames
  3. `_distance_gain()` -> always < 1.0 (max 0.98), so one step can never
     cover the whole offset (this was the actual overshoot cause)
  4. **first-contact cap**: while `_samples < 3`, bound the step by
     * worst-case travel (`counts * px * lock_sens_guard`, guard=5.0)
     * vs `dist` — because the config estimate can be 4x off and the
       estimate-based clamps cannot save you when the estimate itself is wrong
  5. **uncertainty-aware clamp**: `_calib_uncertainty()` returns the residual
     EMA error (`0.5**n`) plus observation spread; clamps reason with an
     upper bound, not the point estimate (the estimate always lags one frame)
  6. **last-mile per-axis guard**: in the final px, one count may already
     exceed what is left on that axis -> floor the counts instead of hopping
     over the head
  7. minimum-step guarantee now refuses to send 1 count when 1 count > the
     remaining offset (this caused a ±1 px flicker onto the wrong side)
- `_detect_human_movement()` compares the offset change against what OUR last
  step should have achieved (`_pending_expected` counts × live px/count).
  Earlier versions compared raw offsets and fired constantly during a normal
  approach, throttling gain to 0.45x and making the aim crawl.

**Proof harnesses (offline, no game needed):**
- `tools/test_aim_lock.py` — 4 scenarios with an honest overshoot detector
  (sign crossing OR error growth), hidden true sensitivity.
- `tools/test_aim_sweep.py` — 26 cases: sens 0.2x…4.0x of the config estimate
  × 3 distances + inverted Y. **Regression gate: must print `failures: 0`.**
  Current result: 0 failures, lock in 5–23 frames, no overshoot anywhere.
  Final error 2–8 px (well inside a head hitbox).

**Config knobs** (tuning only, code is correct without touching them):
`lock_max_zone_px`, `lock_max_move_px`, `lock_settle_px`, `lock_dwell_frames`,
`lock_snap_px`, `lock_snap_gain`, `lock_precise_gain`, `lock_sens_guard`,
`lock_human_px_per_frame`. The stale `lock_absolute_move` key was removed from
both `config.ini` and `config_watcher.py` and replaced by `lock_sens_guard`.

**Environment gotcha:** `import logic.mouse` pulls in `logic.visual` ->
`logic.capture`, which instantiates a DXGI capture device at import time.
If the screen is locked/asleep this raises `ValueError: NULL COM pointer
access`. Stub `bettercam` (width/height/start/get_latest_frame) to test
the controller headless.

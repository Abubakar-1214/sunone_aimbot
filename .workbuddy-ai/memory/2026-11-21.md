# 2026-11-21 Work Log

## Aimbot Mouse Lock Issue Fix - COMPLETE (v2)

### Problem
- Model detects enemy but mouse goes to detected position SLOWLY
- Mouse reaches target but doesn't LOCK - keeps oscillating/moving around
- Need: mouse should JUMP instantly to detected position and LOCK there

### Root Cause (Final Diagnosis)
The core issue was `mouse_calib_scale = 0.24` which made `counts_per_px = 0.42`.
This means each pixel of target offset only produced 0.42 hardware counts.
Since `win32api.mouse_event` only accepts integer counts, small movements rounded to 0 or 1 counts.
Result: mouse moved ~42% of needed distance per frame, never fully reaching target → oscillation + no lock.

### Fix Applied

#### 1. Calibration Scale Fix (THE KEY FIX)
- `mouse_calib_scale`: 0.24 → **1.0**
- Before: `counts_per_px_x = 0.4261` (42% of distance per frame, rounds to 0)
- After: `counts_per_px_x = 1.7756` (178% of distance, moves FULL distance in one frame)
- Added `mouse_calib_scale` to config_watcher.py defaults and _bind_attributes

#### 2. Direct Snap Movement (mouse.py calc_movement rewrite)
- **Removed PID controller** (pid_enabled = False) - PID was causing slow ramp-up and oscillation
- **Single unified approach**: every frame, move mouse EXACTLY to target center
- `snap_gain = 1.0` for ALL distances (far, medium, close)
- Deadzone: 2.0px (rock-solid lock when at center)
- Velocity feedforward from Kalman for moving targets (0.8x)

#### 3. Simulation Results (verified)
- 90px target: Frame 0 moves 90px → 0.2px remaining → Frame 1 LOCKED
- 15px target: Frame 0 moves 15px → 0.2px remaining → LOCKED
- 2px target: Frame 0 moves 2px → 0.3px remaining → LOCKED
- Every distance converges in 1-2 frames

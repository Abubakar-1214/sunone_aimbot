## Mouse Movement — ROOT CAUSE FOUND & FIXED (Attempt 10 — FINAL)

### Root Cause — THREE bugs:
1. **Wrong denominator**: `calc_movement()` used `FOV / detection_window_width` instead of `FOV / display_width`. Detection window is a CROP — FOV spans full screen. Was 3.6x too large → overshoot → circling.
2. **Wrong FOV values**: Config had FOV=106x200 but user plays 1152x864 (4:3). CS2 at 4:3 has H-FOV=90°, V-FOV=73.74°. Fixed with auto-FOV calculation from aspect ratio.
3. **No lock mechanism**: Deadzone was 3px (too small for YOLO jitter). Gain was always 1.0 (full snap every frame). When detection jittered 2-5px, mouse kept moving back-and-forth → no lock.

### Final Fix — Three-Zone Lock System
```python
# Zone 1: LOCK (dist <= 8px deadzone)
#   Mouse stops completely. Creates "lock" feeling.

# Zone 2: NEAR (8px < dist <= 20px snap_zone)
#   Gain ramps from 0.35 to 1.0. Smooth approach, no overshoot/jitter.

# Zone 3: FAR (dist > 20px)
#   Full 100% snap. Goes directly to target.

# Auto-FOV from aspect ratio (CS2/Source engine)
v_fov = 73.74  # always
h_fov = 2 * atan(tan(v_fov/2) * aspect)  # 90° for 4:3

counts_per_px_x = 1.776
counts_per_px_y = 1.940
```
